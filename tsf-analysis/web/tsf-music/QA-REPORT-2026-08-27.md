### Why DEGRADED (root cause, 2026-08-27 12:58 IST evidence)

Direct Node fetch repro:

```
VISIONOS → LOGIN_REQUIRED (416ms)
IOS      → "no audio url" (487ms) — playability OK but streamingData has 0 urls
ANDROID_VR / IOS_MUSIC / ANDROID_MUSIC → LOGIN_REQUIRED
Piped/Invidious → timeout 1500ms (all 7 instances)
```

`IOS` detail: direct `curl`/Node against `youtubei/v1/player` returns `playabilityStatus: OK` with 23 adaptiveFormats but **all `f.url` are missing**; only `serverAbrStreamingUrl` is present. This is YouTube's SABR (Server-guided Adaptive Bitrate) migration — direct URLs are no longer emitted for app clients. The resolver at `src/lib/ytm/stream.ts:161-167` filters on `f.url` so it correctly reports "no audio url". `VISIONOS` now also returns `LOGIN_REQUIRED` where it was the field-verified workhorse on 2026-08-27 morning. Network IP unchanged; behavior changed between verification windows. Manual `curl` to `youtubei` from same Mac succeeds (not firewall) — failure is in provider contract, not network.

Fallback chain after YouTube:
- When `title`+`artist` are supplied, `/api/stream` correctly reaches iTunes preview. Verified:
  `curl "/api/stream?id=xTvyyoF_LZY&title=Shape%20of%20You&artist=Ed%20Sheeran&fresh=1&proxy=1" → 206 audio/x-m4p 977,645 bytes x-stream-provider: itunes-preview` (30s REAL studio clip).
- `AudioEngine.tsx:284-285` DOES pass `&title=…&artist=…` on every play and `&fresh=1` on error retry, so **real phone playback will be 30s iTunes clips**, not synth, unless a stale cache row still holds a synth URL.
- Without `title` param, it skips iTunes and goes straight to `tsf-synth`.

## Bugs found

1. **BLOCKER — YouTube provider chain 100% failing; all tracks fall back to synth/iTunes preview**
   - Every `GET /api/stream?proxy=1` returns `x-stream-provider: tsf-synth` (no title) or `itunes-preview` (title supplied). No track returns real full-length googlevideo audio.
   - Repro: `bun run dev` → `curl -s -D - "http://localhost:3000/api/stream?id=xTvyyoF_LZY&proxy=1" --max-time 20` → observe `x-stream-provider: tsf-synth`. Health endpoint shows `innertube-IOS: "no audio url"`, `innertube-VISIONOS: LOGIN_REQUIRED`, Piped/Invidious timeouts.
   - Suspected: `src/lib/ytm/stream.ts:135-183` `resolveInnertube()` filters `f.url` which YouTube no longer populates (SABR migration — only `serverAbrStreamingUrl` present). `src/lib/ytm/clients.ts` VISIONOS/IOS client versions may need bump or PO Token. Piped/Invidious relay list dead.
   - Workaround in place: AudioEngine passes `title`+`artist` → phones get 30s real iTunes clip. Better than silence, NOT full-length.

2. **MAJOR — Stream resolve latency ~15-20s (target ≤3s)**
   - `src/lib/ytm/stream.ts:331-342` races `Promise.any` over 6 Innertube + Piped + Invidious, each with 1.5–4s timeout, before falling to iTunes/synth. Even when all fail, we wait for the slowest timeout. Synth render (`src/lib/synth/render.ts`) is synchronous WAV generation.

3. **MINOR — B14 nonsense search not empty** (YTM fuzzy returns 39 tracks for gibberish) — robust, upstream behavior.

4. **MINOR — `npm install` broken by icu-minify version mismatch** (`next@16.1.3` pulls `icu-minify@^4.14.0` not yet published); bun works. Stray `~/package.json` also interferes.

5. **MINOR — B15 cache replay not faster for synth path** (cache stores URL not bytes; synth re-renders every request).

6. **INFO — B13 non-proxy redirect no longer 307** while providers are down (correct degraded behavior; will resume 307 once providers recover).

## Final verdict: NOT READY for native phase

**One-line reason:** Server-side playback is 100% degraded to synthetic / 30s preview audio due to YouTube SABR migration breaking the Innertube provider chain, with 15–20s resolve latency failing the ≤3s tap-to-sound target, and no real-device lock-screen/background verification completed.

**Must-fix before native:**
1. Restore full-length audio: implement SABR (`serverAbrStreamingUrl`) handling or alternative extraction (study Musify's vendored `youtube_explode_dart` fork — it solves exactly this), or alternative providers.
2. Reduce resolve latency to ≤3s (fail-fast / parallel tweaks / cache tuning).
3. Owner to execute C1–C5 on Android Chrome and iPhone Safari, including screenshots in `qa-evidence/`.
